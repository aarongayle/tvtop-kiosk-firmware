# TV-Top Kiosk firmware — architecture

Targets: Raspberry Pi Pico 2 W (RP2350, 520 KB SRAM), which reaches **1920×1080p30**, and
Raspberry Pi Pico W (RP2040, 264 KB SRAM, 2 MB flash), which tops out at **1280×720p30**. Both
overclock to 372 MHz at 1.30 V for a 372 or 744 Mbit/s TMDS bit clock. DVI comes out on GPIO12-19
through any breakout following libdvi's `pico_sock_cfg` pinout (see [HARDWARE.md](HARDWARE.md)).

The device speaks version 3 of the TV-Top kiosk protocol and must draw what the platform's own SVG
renderer draws. Those live in the TV-Top app repository, which is not public; the ops the kiosk
implements and how it interprets them are documented in [RENDERING.md](RENDERING.md).

## The three hard constraints and how each is met

1. **No framebuffer fits.** 1280×720 at even 4 bpp is 460 KB. We keep the frame as **run-length
   spans** ("line pool"): each scanline is a list of `(palette index, run length)` byte pairs. Flat
   vector art (rects, polygons, text) compresses to a few dozen spans per line. Measured with the
   host tool (`host/render_frame --stats`), a full Global Conquest board needs well under 100 KB.
2. **TMDS encoding of 1280 pixels per line must fit in a 44 µs scanline on one Cortex-M0+.** Every
   palette colour is quantised so each 8-bit component is one of the **52 DC-balanced TMDS
   values** (`tmds_balanced_levels`). A balanced symbol has zero disparity, so the encoder needs no
   running-disparity state and a run of N pixels is N/2 copies of one 32-bit word (two symbols per
   word, `DVI_SYMBOLS_PER_WORD=2`). Runs are written with unrolled store-multiples; short runs are
   special-cased. Quantisation error is at most ±8/255 per channel, invisible on a TV.
3. **Geometry does not fit in RAM either.** The static set of a board (up to 320 KB of JSON, up to
   ~35k source vertices for Europe) is decoded *while it streams in* into a **flash-resident
   geometry cache** (`geom` store, flash region after the firmware). The renderer reads polygon
   vertices straight from XIP flash. Only the dynamic frame (≤16 KB JSON) becomes RAM structures.

## Pipeline

```
 core 0                                                         core 1 (all code + data in SRAM)
 ──────────────────────────────────────────────────────────     ──────────────────────────────
 kiosk_loop: GET next_url ──► http_client (lwIP raw/altcp)      scanout: for each line y:
     │ body bytes (main context)                                   spans = linepool.line[y]
     ▼                                                             tmds_rle_encode_line(spans → 3 lane buffers)
 frame_decoder (streaming JSON → frame_t ops/arena/paints,         queue to PicoDVI DMA (libdvi)
     static defs → path recorder → flattener → geom store/flash)
     │
     ▼
 frame_render: for each band of KIOSK_BAND_LINES lines:
     raster ops in order into 8 bpp band buffer (palette indices)
     RLE each line → linepool_alloc/commit (per-line atomic swap: a "wipe" update)
```

Everything in `src/common/` is portable C (no SDK headers) and is compiled for the host too
(`host/`), where fixture frames (`test/fixtures/*.json`, real output of the kiosk server) are
rendered to PNG, compared against `resvg` renderings of the equivalent SVG, and measured (pool bytes,
spans per line, edge visits).

## Coordinate conventions

* Wire canvas is 1280×720. The decoder scales to the output mode with `k = out_w/1280` and, for
  non-16:9 modes, letterboxes with an integer offset. **After decoding, everything is in device
  space.**
* `px8`: fixed point, 1/8 pixel, `int32_t` in APIs, `int16_t` in stored geometry (range ±4096 px,
  clamped). Pixel `i` on a scanline `y` is sampled at its centre: `(i*8+4, y*8+4)`.
* Polygon fill: pixel covered iff its centre x is in `[xa, xb)` of a nonzero-winding span (or
  even-odd when requested). Rects with integer coordinates therefore cover exactly `w` pixels.
* Text: `y` is the alphabetic baseline; `x` is the anchor for align 0/1/2 (left/centre/right).

## Colour

`colour_parse` accepts `#rrggbb`, `#rgb`, `#rrggbbaa`, `#rgba` and a small CSS name table; anything
else (`url(#…)`, `none`) means *draw nothing* — exactly what the browser does for the pattern fills
that the emitter currently leaks. The palette is **append-only across frames** so the lines of the
previous frame still on screen keep their colours during the wipe; it is reset only when it is
nearly full at the start of a frame. Alpha (from `#rgba`) and glyph anti-aliasing both go through
`palette_blend(bg, fg, level)`, which allocates the mixed colour as a palette entry (cached).

## Text

* Bitmap faces (Roboto Regular/Bold, 2 bpp coverage, sizes 10–26 px, generated by `tools/fontgen`
  with stb_truetype) are used when `size*k ≤ KIOSK_FONT_BITMAP_MAX`; snap to the nearest size.
* Larger text is rendered **exactly** from glyph outlines (quadratic contours in the same blob) by
  the anti-aliased polygon filler (`raster_fill_poly_aa`, exact x-coverage, SS sub-rows). No glyph
  cache is needed: glyphs are rasterised per band they intersect.
* Codepoints missing from the blob advance by the space width and draw nothing (emoji).

## Memory plan (RP2040, KIOSK_TLS=0) — measured 2026-09-14

| Block | KB |
|---|---|
| line pool (`KIOSK_LINEPOOL_BYTES`) + line table | 84 + 6 |
| scratch union (render: 8×1280 band + raster scratch; decode: 20 KB path recorder + geometry index) | 28 |
| frame_t (1000 ops × 16 B, 6 KB arena, paints) | 23 |
| TMDS line buffers (3 × 3 lanes × 640 words) | 23 |
| lwIP (pbuf pool 12 KB, heap 4 KB, segments) + cyw43 state | ~20 |
| RAM-resident code (libdvi hot paths, encoder, core-1 loop) | ~8 |
| everything else (.data, tinyusb, portal connections, palette LUTs, decoder) | ~35 |
| **total static** | **227** |
| heap left for lwIP/cyw43 dynamic needs | 30 |
| stacks: core 0 4 KB (SCRATCH_Y), core 1 2 KB (SCRATCH_X) | 6 |

The largest real frame (the Global Conquest Europe board) needs 77 KB of line pool at 720p.
With `KIOSK_TLS=1` (mbedTLS) add ~60 KB (16 KB TLS record buffer, handshake heap, 32 KB TCP
window); the pool shrinks to 56 KB and oversized frames degrade to duplicated lines. `src/common/
kiosk_config.h` holds every tunable; the CMake option `KIOSK_TLS` picks the profile.

## Flash plan (2 MB)

| Region | Offset | Size |
|---|---|---|
| firmware (code, cyw43 firmware, fonts blob) | 0x000000 | ≤ 1 MB (checked at link) |
| geometry cache (`geom_flash`) | `KIOSK_GEOM_FLASH_OFFSET` = 0x100000 | 0xEF000 (956 KB) |
| config sector | 0x1FF000 | 4 KB |

Flash writes happen only on core 0 with core-0 interrupts disabled; core 1 never executes from or
reads flash (verified by placing every core-1 function in SRAM and all its data in SRAM), so the
scanout is unaffected by erases and page programs. The geometry region is erased block by block as
it fills and its 8 KB header (magic, static id, index) is written **last**, so a power cut leaves
either the old complete set or no set. The XIP cache is invalidated after a commit.

## Device state machine (`kiosk_loop`)

```
BOOT ─ no Wi-Fi creds ──► PROVISION (SoftAP "TVTOP-xxxx" + captive portal + USB console)
     └ creds ──────────► CONNECTING (screen: "Connecting to <ssid>…")
CONNECTED ─ no token ──► GET /v1/register?model=&fw=  → store token, next_url
LOOP:  GET next_url (receive timeout 45 s)
         200 → decode; if static id unknown and no defs → keep frame, next = /v1/config
               else render, persist next_url when its shape (minus rev) changed
         304 → nothing; 404 → next = /v1/config?t= (3× from /v1/config itself → re-register);  error → backoff 1..60 s full jitter,
               after 2 failures overlay the offline indicator on the last good frame
```
Firmware-owned screens are themselves JSON frames (`builtin_frames.c`) drawn by the same renderer.

## Verification strategy

* Host unit tests (`host/tests`) for: TMDS balance/decode round-trip, colour parsing, JSON
  streaming (chunk boundaries, escapes), path flattening (all SVG commands incl. arcs), polygon
  rasteriser (winding, even-odd, clipping, degenerate), RLE round trip, encoder vs reference.
* Fixture rendering: every `test/fixtures/*.json` renders without error; PNGs are compared against
  `resvg` renders of `tools/render-reference.mjs` output (same fonts) with a per-fixture tolerance.
* Device: `stats` on the USB console prints render time, pool bytes, late scanlines, heap.
